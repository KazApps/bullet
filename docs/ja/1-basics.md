# 1. NNUEの基礎

## 単純なフィードフォワードネットワーク

### 入力

チェス用の基本的なニューラルネットワークへの入力は、`768 = 2 x 6 x 64`のゼロまたは1のベクトルです。ここで、特定のインデックスの1は、特定のマスに特定の駒が存在することを示し、ゼロはその駒が存在しないことを示します。

標準的な方法は、`白ポーン = 0, 白ナイト = 1, ..., 黒ポーン = 6, ..., 黒キング = 11`を設定し、マス`Square`にある各駒`Piece`に対して、入力ベクトルの`64 * Piece + Square`番目の要素を1に設定することです。

今後は、この入力ベクトルを$\mathbf{x}$と表記します。

### 隠れ層

`768 -> N -> 1`ネットワークの隠れ層は、`N`次元のベクトルであり、入力ベクトルの関数です。これについて、いくつかの新しいものを定義する必要があります。

- $H$: 隠れ層の重み、`Nx768`次元の行列
- $\mathbf{b}$: 隠れ層のバイアス、N次元のベクトル
- $\rho$: 活性化関数、任意のベクトルに要素ごとに作用する

これらを用いて、アキュムレータ$a = H \mathbf{x} + b$を定義し、隠れ層自体を$\mathbf{h} = \rho (\mathbf{a})$とします。

### 出力層

出力$y$は、チェスエンジンで使用する必要があるため、スカラー値です。以下を定義します。

- $O$: 出力重み、`1xN`次元の行列
- $c$: 出力バイアス、スカラー定数

すると、出力は$y = O \mathbf{h} + c$と定義されます。`1xN`行列とN次元ベクトルの積は`1x1`行列、つまりスカラーであることに注意してください（$O$をベクトルとして定義し、ドット積を使用することもできましたが、これにより一貫性が保たれます）。

### 全体をまとめる

完全な計算を書き出すと、次のようになります。

$$
y(\mathbf{x}) = O \rho( H \mathbf{x} + \mathbf{b} ) + c
$$

## パースペクティブネットワーク

パースペクティブネットワークアーキテクチャ`768 -> Nx2 -> 1`は、2つの入力セット$\mathbf{x}$と$\mathbf{\hat{x}}$があることを除いて、非常によく似ています。

前のネットワークとは異なり、$\mathbf{x}$は白視点からのものではなく、代わりに駒の種類は手番側の視点から`味方ポーン = 0, ..., 敵キング = 11`とラベル付けされ、$\mathbf{\hat{x}}$は同じですが、相手側の視点からのものです。

現在、2つのアキュムレータ$\mathbf{a} = H \mathbf{x} + \mathbf{b}$と$\mathbf{\hat{a}} = H \mathbf{\hat{x}} + \mathbf{b}$があり、出力は次のように与えられます。

$$
y = O \rho(concat(\mathbf{a}, \mathbf{\hat{a}})) + c
$$

この場合、$O$を$O_1$と$O_2$に分割して、同等に

$$
y = O_1 \rho(\mathbf{a}) + O_2 \rho(\mathbf{\hat{a}}) + c
$$

とすることができます。これは一般的に推論で使用する形式です。

## 初心者向けの落とし穴

### 貧弱な初心者向けリソース

#### 著者の強力なNNUEエンジンに裏打ちされていない、NNUEに関するほとんどすべての記事/ブログ投稿/書籍

- 確かに、それらはNNUEのコアコンセプトをうまく説明しているかもしれません
- それ以外のことは通常、関連する証拠がほとんどまたはまったくない、悪いアドバイスになります

#### Stockfishのネットワークアーキテクチャ

- 具体的には、実際のSFネットワーク（明らかに非常に優れています）ではなく、**アーキテクチャ**を指します
- SFアーキテクチャは、多くのエンジンによってパロディ化されています
- SFアーキテクチャの多くの側面は、実際にELOを獲得するために**多大な**労力、データ量、および/またはトレーニング時間/複雑さを必要とします
- その結果、エンジンは（そして初心者にとってはそうなる可能性が高い）、はるかに単純なアーキテクチャと比較して、SFアーキテクチャで実際にELOを*失う*可能性があります

#### [nnue-pytorchのnnue.md](https://github.com/official-stockfish/nnue-pytorch/blob/master/docs/nnue.md)

- 一般的なSF NNUEの歴史と、いくつかのより高度なものに関する優れたリソース
- 上記の続き
    - これはStockfish NNUEに関するドキュメントです
    - あなたはStockfishを書いていません
- 初心者にとって必要な情報よりもはるかに多くの情報が含まれているため、一般的に混乱する可能性があります
- おそらく最も合理的な開始アーキテクチャを[おもちゃの例](https://github.com/official-stockfish/nnue-pytorch/blob/master/docs/nnue.md#a-simple-input-feature-set)として扱います
- その内容の大部分に関して、一般的に時代遅れです

### スキップされた進行

一般的に、単純なものから始めて、複雑さを段階的に増やし、各段階的なステップが実際にELOを獲得していることを確認することをお勧めします。

以下の初心者向けの落とし穴に特に関連するのは、この記事の執筆時点では、Alexandria 7.0.0がCCRL Blitz 1CPUで6位であり、そのネットワークアーキテクチャは`(768->1536)x2->1x8`です。つまり、*入力バケットがなく*、隠れ層が1つだけです。

#### 大規模な入力特徴セット

- まずは基本的な768入力から始めましょう
- 最初はHalfKA/HalfKPのようなものに十分なデータがないでしょう（またはおそらく永遠に、カスタムバケットスキームは一般的に少ないデータでより役立ちます）

#### 2つ以上の隠れ層

- 通常、最初の隠れ層のサイズを大きくする方が有益です（少なくとも1024まで）
- それ以上の層は固定ノードでゲインしますが、速度の低下により多くのELOを失わないようにするのは簡単ではありません
- 手動SIMDと十分に検討された量子化技術が必要です
